# 音源曲库与本期选曲范围

## 首次启用

依次完成基础结构、管理工作流、完整性、测试模式、QQ 参与和账号管理迁移，最后执行 supabase-song-catalog.sql。已有 QQ 账号和账号管理功能的数据库只需执行最后一份曲库迁移。迁移保留原歌曲、票数和历史记录；不可使用清空重建脚本代替增量升级。

同步发布用户端、管理端和 QQ 后端。QQ 后端继续使用已有 Supabase 服务端密钥；健康检查新增 qq_catalog_health，缺少迁移或旧迁移覆盖网关时发布失败。重新执行旧迁移后须最后再次执行曲库迁移。迁移、录入曲库与发布之间应安排维护窗口。

后台进入“音源曲库”，录入歌曲名、歌手、音源地址或内部编号、时长和备注。不同版本应在歌名中注明。只有工作人员实际核对音源并打开“确认有音源”和“允许出现在曲库”，歌曲才会出现在用户搜索结果中。空音源不能设为可用；音源地址、内部备注仅管理员可读。

本版使用广播台人工维护的音源目录，不附带音乐文件，不接第三方平台搜索、下载或自动音源巡检。只有分享链接也可能无法实际播放，标记可用前需要工作人员确认。空曲库会显示准备中；未收录歌曲暂不能投稿。

## 特殊节目开关

后台白名单按当前征集期保存，可按歌名/歌手搜索并跨页勾选。可选开始、结束时间按管理设备本地时区输入，保存为带时区的时间；开始留空立即生效，结束留空持续到手动关闭。到期由数据库时间判定，自动恢复全部可播曲库，无需定时任务。开关关闭不清空名单，再打开可继续使用。

白名单只接受管理员审核的节目选曲清单。启用空白名单会阻止所有新投稿，界面要求确认。多人保存采用版本校验，过期的修改会被拒绝，需要重新读取。

生效范围是新投稿入口；既有投稿、票数和历史不会被删除，也不会自动停止投票。需要从现有榜单排除歌曲时，使用原有歌曲锁定操作。

## 校验与维护

浏览器提交 catalogId，经同源 QQ 后端验证会话，再由数据库 QQ 网关查询曲库和当前白名单。曲库 ID、启用状态、音源、日期范围在提交时重新检查。旧自由填写入口和曲库内部投稿函数均禁止浏览器直接调用；QQ 封禁、参与额度、限流、重复歌曲和测试期双重授权继续生效。

曲库维护及规则修改写入管理操作日志。重复执行迁移保留数据；全量重建保留曲库、QQ 身份及账号处理，清空征集期和对应白名单规则。

本地数据库测试：在 apps/admin 中执行 node tests/database-song-catalog.cjs。测试使用隔离 PGlite，无线上连接。用户端、后台交互和完整数据库测试分别使用 npm test 与 npm run test:db。
