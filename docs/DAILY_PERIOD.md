# 晚间设置明日征集

管理后台在北京时间 **18:00—23:59** 读取数据成功后，检查明天是否已有正式征集。没有安排时自动弹出「设置明日征集」，默认填写明天的标题、**00:00 开始、18:00 截止**。管理员核对后点击「确认创建征集」保存，可以自行修改标题和时间。

**白天不会自动弹窗，也不会提醒补建。** 需要手动处理时，可从总览或征集期管理点击「快捷设置征集」，选择今天或明天；跨天或多日的特殊安排继续使用「自定义新建」。

弹窗按北京时间计算日期，不受管理员设备时区影响。完整显示年月日、星期和 24 小时制起止时间；不足一小时的征集须再次核对，避免将下午 18:00 错填成凌晨 00:18。手动新建、编辑征集期也有短时段确认提示。

同一账号、同一浏览器标签会话内，每个目标日期自动提示一次；关闭或刷新不会反复弹出，仍可手动打开。新的标签会话可以再次提示。页面一直开着时，进入晚间时段也会检查。

已有与目标日期相交的正式征集时，不自动弹窗、不新建重复期。手动打开会展示现有安排，并可进入原期编辑。修改原期保留歌曲和票数。当前为测试期或已经安排更晚日期时，快捷创建不会切换它。

保存前重新读取征集安排，数据库在同一事务内校验管理员权限、北京时间日期、结束时间及当前期版本。重复保存、多人先后保存同一天会复用已有征集；其他管理员修改过当前期时须重新读取再确认。

## 发布

现有数据库已安装管理工作流、完整性和测试模式迁移后，在 Supabase SQL Editor 完整执行增量脚本 [`supabase-daily-period.sql`](../supabase-daily-period.sql)，然后发布管理端。脚本可重复运行，保留现有歌曲、票数和征集期。缺少迁移时，快捷保存会显示具体升级提示。

新数据库按仓库现有顺序完成各迁移，再执行本脚本。生成的清空重建脚本也已包含本功能，但**已有业务数据的日常升级只运行增量脚本**。

本功能沿用当前系统的单活跃征集期规则：确认创建后旧期立即归档，明天 00:00 前新期不可投稿或投票。如果旧期尚未截止，会先弹出切换确认。没有人在后台确认时不会自动创建，也不需要配置定时任务。前台和 QQ 后端无需为本次功能改动。

本地验证：在 `apps/admin` 执行 `npm test`、`npm run test:db` 和 `npm run build -- --base=/admin/`。测试使用本地数据库与模拟数据，不改动线上征集安排。
